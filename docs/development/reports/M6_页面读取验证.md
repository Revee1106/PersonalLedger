# M6：付款页面读取可行性验证

日期：2026-11-12（Asia/Taipei）。本阶段验证技术前提，不宣称已支持自动记账。

后续结论：用户真机反馈读取不顺利、基本读不到，已暂停推进此路线，转向 [M7 桌面记账卡片](M7_桌面记账卡片.md)。下方场景表是 M6 交付时的验证计划，不是已通过清单；本地同名体验包已由 M7 更新，当前安装包摘要以 M7 为准。

## 依据与目标

用户真机测试支付宝、微信在线付款均没有系统通知。当前通知解析器即使工作正常，也无法覆盖这些无通知场景。常用来源为淘宝、京东、小红书、抖音，以及微信、支付宝。通知渠道降为补充，先评估这些 App 当前付款页面的无障碍可读性。

## 实现范围

- 设置新增「付款页面读取验证」，系统单独授权后仍需点击「同意读取，开始五分钟验证」。每次五分钟，到期停止，进程重启不会恢复采样。
- 系统事件过滤与读取后的根节点包名校验均限制为六个目标包名。仅取当前可见节点，后台串行读取、合并高频事件，限制节点数量、文本长度与采样时间。
- 摘要包含来源、读取时间、节点数、预设成功词与其他状态、最多八个金额候选。成功词按完整标签匹配；商品价格、原价和实付均可能进入金额候选，不据此判定支付成功。仅识别带人民币符号或实付等标签的金额，不能识别所有排版、分隔格式或 WebView。
- 最多保留二十条摘要，仅存当前进程内存；不保存原文、不上传、不写日志。密码字段或检测到验证提示时跳过展示。普通停止保留摘要供查看，清除会同时停止，开始新一轮会清空旧结果。
- 不调用点击、手势、滚动、截图，不获取支付凭据，不写入账本或待确认队列。关闭服务会停止采样；超时、停止、清除或重开后，旧采样结果不能回写新会话。
- 当前服务支持配置是验证白名单，并非真实兼容性清单。非标准版本、极速版、独立商城、分身等包名需要另外验证，不默认扩大权限范围。

## 真机步骤

1. 优先构建并安装 `:app:assembleProbe` 产物：`app/build/outputs/apk/probe/app-probe.apk`。应用名称为「PersonalLedger验证」，包名 `com.eric.personalledger.probe`，可与原账本同时安装，拥有独立的空账本与独立权限。无需覆盖、卸载或清除原应用数据。若自行使用 Debug 包覆盖原应用且签名不一致，先停止覆盖安装并安排数据迁移。
2. 设置 → 付款页面读取验证 → 前往系统开启服务，手动开启「个人账本页面读取验证」。返回后应显示「已连接」。如果系统限制启用，记录提示，不将授权失败记为页面不可读。
3. 点击「同意读取，开始五分钟验证」，切到目标 App。先用已有订单／账单详情验证可读性，再在下一次正常付款时验证实时结果；不要求额外消费。
4. 付款结果页停留片刻，再返回账本验证页，停止读取，记录源 App、系统与 App 版本、跳转路径、成功词、金额候选是否含实付、有无其他金额。不要提供密码、验证码或完整个人订单信息。
5. 对订单未付款、付款失败或取消、退款、转账页面分别检查：不应把它们当成正式消费。本轮只展示提示，没有入账动作。
6. 停止后切回目标 App 再返回，摘要不应新增；清除后列表应为空。五分钟超时后停止；关闭服务再返回应显示未授权／未连接。进程结束后不恢复会话或历史摘要。
7. 记录后清除摘要，并按需在系统关闭服务。测试期间避免浏览无关聊天或订单。
