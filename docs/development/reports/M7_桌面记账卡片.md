# M7：桌面「记一笔」卡片

日期：2026-11-12（Asia/Taipei）。用户已确认以主动快捷记账替代自动读取主线。

## 用户可见行为

- 原生 Android 桌面小组件，默认约 2×1，暖白卡片、黑灰文字和加号；支持调整大小，实际占格和圆角由桌面决定。
- 点击整张卡片，直接打开「记一笔」并聚焦金额框，默认支出、今天与现有默认账户；仍可修改类型、分类、账户、日期、备注，由用户点击保存后入账。
- 应用已打开时也能从卡片进入；如果已有未保存的新增或编辑表单，优先继续该表单，不直接清空草稿。新建表单支持页面重建时恢复草稿。
- 冷启动异步读取账户，不将用户已输入的金额清空；账户加载中提示等待，失败可重试，账户未就绪时保存不可用。
- 设置首屏新增「桌面记账卡片 → 添加到桌面」，仅请求系统弹窗，不把请求发出记为添加成功；不支持应用内添加或用户取消时，可从桌面的小组件／窗口小工具列表手动添加。
- 不读取付款页面，不请求通知／无障碍／悬浮窗权限，不展示金额或余额，不查询账本以更新卡片，不设置周期刷新。

## 实现

`QuickEntryWidgetProvider`、RemoteViews 布局、背景和加号、AppWidgetProviderInfo XML 与 Manifest receiver。不可变、显式 PendingIntent 直接启动 MainActivity 的新增入口；CLEAR_TOP／SINGLE_TOP 避免重复叠加页面。启动动作在 ViewModel 中记录已处理状态，配置重建时不重复消费，进程死亡后重新接受新的桌面点击；不将这个一次性标记持久化到旧首页的 Bundle。保留 Intent 身份供生命周期观察，历史任务恢复不主动新建账目。

保留现有数据库与记账校验。新增表单使用独立会话 key，草稿字段用 rememberSaveable 保存；账户加载完成时补齐无效默认值，不覆盖有效选择。没有实现截图识别、常用模板或账单导入。

## 使用与安装

1. 安装更新包。原 Debug 包的应用 ID 是 `com.eric.personalledger`；独立体验包仍为 `com.eric.personalledger.probe`、名称「PersonalLedger验证」，数据和桌面卡片入口分别指向各自的账本。
2. 设置 → 桌面记账卡片 → 添加到桌面，并在系统弹窗确认。没有弹窗时长按桌面空白处，在小组件／窗口小工具中选择本应用的「记一笔 · 桌面卡片」。
3. 点击卡片输入金额，收起键盘后核对并保存。已有表单时继续该草稿；保存或返回后，下次点击创建新账目。冷启动、应用退到后台、页面重建与从设置页返回均需保持同样的入口语义。
4. 体验包沿用 M6 的本地 Debug 签名，可覆盖本地同签名体验包。不要卸载或清除原账本；若其他来源安装包出现签名不一致，先保留原数据，不能以卸载解决。

## 验证过程与结果

- 使用 M6 的工作区内独立 Gradle 缓存、Android 用户目录和源码副本构建，JDK 25／Gradle 9.6.0，正式项目的 JDK 21 条件未修改；不自动下载 SDK。
- 自有模拟器 `LedgerWidgetM7`，Android 17／API 37，串口 `emulator-5580`；在工作区独立创建数据目录，未修改原用户 AVD 的数据，没有连接或操作用户真机。
- 初次完整构建：Debug、Probe、AndroidTest APK、19 项 JVM 测试及 Lint 通过。UI 测试首先暴露原 Espresso 3.5.1 在 API 37 调用 InputManager.getInstance 的兼容问题，测试依赖更新为 Espresso 3.7.0／AndroidX JUnit 1.3.0（仅测试依赖）。
- 已通过应用内按钮显示系统添加弹窗，并确认将卡片加入真实模拟器桌面，查看实际布局。未开启通知或无障碍权限。截图为本轮模拟器 Debug 包，不是设计图。
- 已验证热启动的卡片 PendingIntent 和 RemoteViews 实际点击；随后调整启动动作的消费方式以保持生命周期 Intent 身份，复测冷启动与草稿重建。
- 冷启动焦点检查发现窗口就绪前请求焦点不稳定，已改为等待窗口获得焦点并完成一帧布局后请求，仅在每次表单创建时执行一次，避免从后台或日期弹窗返回时抢走用户当前输入焦点。
- 最终完整构建 `:app:assembleDebug :app:assembleProbe :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:lintDebug` 通过，`BUILD SUCCESSFUL in 1m 12s`。19 项 JVM 测试全部通过；Lint 为 0 errors、18 warnings、4 hints。
- 最终 APK 安装到自有模拟器后，完整仪器测试 **12 项通过**：7 项数据库、1 项上下文、4 项卡片／表单 UI。覆盖冷启动后金额聚焦与账户加载、热启动 PendingIntent 与重复点击保留金额、页面重建保留草稿、已注册 provider 的 RemoteViews 实际点击。记录：`app/build/reports/m7/instrumentation-process-state.log`。
