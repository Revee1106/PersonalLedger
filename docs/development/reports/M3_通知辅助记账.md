# M3：支付通知辅助记账

记录日期：2026-11-12。实现与测试证据来自本项目源码及11月11日已执行的测试报告；最终设备界面结果另见M4。

## 已实现的流程

1. 用户在设置页阅读用途，主动打开系统通知访问；Android13及以上单独申请发送提醒权限。拒绝或撤销后仍能手动记账。
2. `PaymentNotificationListenerService`仅处理微信`com.tencent.mm`、支付宝`com.eg.android.AlipayGphone`，跳过分组汇总和其他来源。优先使用展开正文，避免将同一通知的简短／展开版本重复拼接。
3. `NotificationParser`筛选消费成功线索。退款、转账、红包、收款、失败等不作为支出；金额隐藏、格式不合法或多个金额进入人工核对，不直接计入账本。
4. 包名、系统通知key及事件时间生成SHA-256候选ID；事件时间优先取notification.when，没有有效值时回退postTime。候选只保存来源、金额、时间、分类、核对原因与处理状态，不保存全文或原始key。
5. 新候选入库后尝试发送通用系统提醒，默认锁屏不显示金额，使用不可变PendingIntent打开App待确认页；不提供后台广播直接记账入口。
6. 用户在App内核对金额、分类、账户、日期和备注，再确认或忽略。确认与正式账目插入在同一SQLite事务完成，并用候选唯一约束保证最多一次入账；确认／忽略成功后取消对应提醒。

## 重复、重连与错误处理

- 同一事件更新复用候选，旧接收时间不会覆盖较新内容。
- 已确认或忽略的候选不因重放恢复为待确认；监听重连会重新检查仍活跃的通知。
- 同一key的不同事件时间分开处理，不按相同金额或邻近时间合并消费。
- 监听端串行处理数据库写入，受控存储异常不会记录通知全文；撤权期间读取活跃通知的安全异常被处理。
- 提醒未授权时仍保留候选；设置页分别显示通知访问与提醒发送状态，并保留直接打开系统提醒设置的入口。

## 验证边界

- 上述通知数据为合成样本，数据库仪器测试没有伪装成真实微信／支付宝支付测试。
- 系统提醒投递、权限撤销、锁屏和第三方支付完整链路仍需在用户实际手机上按支付场景核实；不能由解析测试推断覆盖率。
- 第三方缺少、复用或改变事件时间时，可能出现重复候选或漏识别；系统通知也不保证每笔支付都有可读金额。用户必须核对实际支付记录。
- 微信聊天等含类似文字的通知可能成为误报线索，候选不等于交易流水；用户可忽略。
- 淘宝、京东等其他购物App未作兼容承诺；当前没有无障碍、短信读取、悬浮窗、真实第三方登录或云同步。
