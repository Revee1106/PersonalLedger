# M1：本地账本与领域规则

日期：2026-11-11（Asia/Taipei）

## 实现

- `domain/` 定义账目、账户、金额、收支聚合、本地月份边界及通知文本解析。
- 金额以 `Long` 分存储；输入只接受正数和最多两位小数，避免浮点换算。分类汇总和余额均由账目计算；转账只改变账户余额，不进入月收入/支出。
- `data/SqliteLedgerRepository.kt` 使用版本 1 的 SQLiteOpenHelper 数据库；包含账户、账目、预算和通知候选表、外键、检查约束、索引与外键约束。首次打开只创建“现金”和“银行卡”账户，账目为空。
- 账目修改/删除、预算、候选状态保存在本地数据库。候选确认在一个 SQLite 事务中插入账目并改变状态；候选 ID 唯一约束和状态检查使重复确认最多入账一次。相同通知键的更新合并为一个待确认项；已处理项不会被重复通知复活。
- 数据库不记日志、不保存原通知标题/正文；应用关闭系统备份，并对 cloud backup 与设备迁移规则明确排除数据库。相关 Android 官方说明：[Auto Backup 与数据迁移规则](https://developer.android.com/identity/data/autobackup)。SQLiteOpenHelper 创建/升级与事务行为见 [Android SQLiteOpenHelper API](https://developer.android.com/reference/android/database/sqlite/SQLiteOpenHelper)。

## TDD 与实际验证

1. 先新增领域测试并运行 `testDebugUnitTest`：编译在未实现的 `MoneyInput`、`LedgerRules`、`NotificationParser` 处失败，形成目标行为缺失的 RED。
2. 实现领域规则后，重跑同一测试目标：通过。JUnit XML 报告显示 7 个测试、0 失败、0 错误，包含 0.10 + 0.20 精确分值、非法金额、收入/支出汇总、转账中性、本地月界线、可信来源与通知歧义、退款/转账排除和通知身份稳定。
3. SQLite 仪器测试先对缺失的 repository API 运行 `compileDebugAndroidTestKotlin` 得到预期 RED；实现仓储后该目标通过，`testDebugUnitTest compileDebugAndroidTestKotlin` 也以 `BUILD SUCCESSFUL` 完成。
4. 仪器测试源码覆盖首次空账本、重开持久化、修改/删除、转账余额、候选更新幂等、重复确认、忽略候选和预算重开/清除。**仪器测试没有实际运行**：协调者报告现有 Pixel 3a AVD 因主机 commit 余量约 1,064 MB、低于约 2,560 MB 的启动需求而退出，adb 设备列表为空。不能据此宣称 SQLite 重启持久化已实测通过。

测试文件：`app/src/test/java/com/eric/personalledger/domain/LedgerRulesTest.kt`、`app/src/androidTest/java/com/eric/personalledger/data/SqliteLedgerRepositoryTest.kt`。

## 限制与下一步

- M1 持久化与去重实现已完成，自动仪器测试已编译；实际数据库运行验证待设备资源恢复。
- 通知解析仅面向微信和支付宝常见中文支付文本的保守首轮适配；无真实通知样本，覆盖率未验证。未清楚提取唯一金额或交易类型时不会直接入账；本地提醒与修改流程会要求用户确认。
- 下一步 M2 使用数据库状态实现首页、记账、统计、账户设置和空状态，再进入 M3 通知监听服务和候选处理界面。
