# GPT-6 Luna · Max：实施任务书

## 目标

你负责把用户已确认的 UI 变为真实可用的原生安卓本地记账 App，并实现通知辅助记账流程。执行 M0–M4，具体要求以同目录 `开发计划.md` 为准。用户已确认实际模型 `gpt-6-luna`、推理级别 `max`；不要更换模型或再派子代理。

## 开始时必须阅读

1. 根目录 `task_plan.md`、`findings.md`、`progress.md`。
2. `docs/development/开发计划.md` 和本文件。
3. `design/v1/设计说明.md`、`design/v1/index.html`；查看两张设计总览图片。
4. 当前 Gradle 文件、入口和主题，以及运行时提供的用户 AGENTS.md 指令。
5. 本地 tdd-workflow 技能；业务逻辑先写能被实际执行的失败测试，再实现与验证。安卓相关 API 与新增依赖行为不确定时先查官方文档。

## 文件所有权

你拥有 `app/**`、必要的根 Gradle 构建文件与 `gradle/**`，以及 `docs/development/reports/**`。主协调者负责根规划文件和本任务书。你不是独自在代码库工作，不得回退他人和用户的改动；修改前检查现状并适应已有修改。不要编辑已确认的 `design/v1/**`，不要修改用户级配置、凭据、SDK 安装路径或用户数据。

## 实施顺序

- 首先报告 M0 基线构建、设备可用性和预计需要的最小构建改动。
- 接着实现 M1 本地模型、持久化、金额和统计。该阶段达成后发送进度，继续 M2。
- M2 用真实数据库状态驱动已确认的原生界面，不把设计稿示例数值写死；优先保证空账本、记账、编辑和统计可用。
- M3 将通知适配与解析分离，再接待确认队列、提醒和确认流程。微信／支付宝通知覆盖率没有真机证据时不能写成已验证。
- M4 整合测试、构建 Debug APK、输出报告。M0–M4 之间无需用户重复授权，可继续独立步骤。

## 必守边界

- 金额模型使用整数分；转账不计入收支；数据库更新使用事务。
- 未确认或已忽略的候选不进入正式收支；重复确认不能重复入账。
- 不硬编码测试验证码来冒充手机号认证；未配置的第三方登录诚实展示未配置，并允许本地使用。
- 不增加无障碍、短信读取、悬浮窗或定位权限；不绕过系统隐私控制。
- 无完整可靠金额时不猜测入账；营销、退款、隐私隐藏通知必须有保守处理。
- 先保留 AGP 9.5.1／Gradle 9.6.0／SDK 37，只有基于具体错误的必要变更才调整，并报告理由。
- 不提交、推送、发布、创建付费作业或远程服务；当前工作区未确认有 Git，不要初始化仓库。
- 没有设备时不要谎报原生截图或仪器测试。不要用 HTML 截图替代原生验证。
- 不以写了测试文件代替运行测试；构建失败不能冒充通过，环境问题与产品缺陷分别列出。

## 汇报契约

每个里程碑向协调者发送简短消息，并写 `docs/development/reports/Mx_*.md`：

1. 完成的功能和关键文件。
2. 实际运行命令、通过／失败及原因；失败与恢复均记录。
3. 下一步和依赖；尚待真机验证的内容。

最终提供 APK 绝对路径、测试证据、已知限制。你不能修改主计划状态或替协调者宣告全部验收完成。
